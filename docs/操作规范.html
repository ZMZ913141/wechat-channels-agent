1登录失败：到底有没有“时效性”？

先给结论：登录态不是按小时过期的，但确实会“突然失效”。分清“平台原因”和“被你弄乱”两类，才能对症下药。

现象本质是否你的操作导致处理
隔几天要重新扫码 视频号登录态存于每个账号独立的浏览器档案 user_data_dir（如 profiles/default），平台 token 通常维持数天~数周，但平台侧可随时让 token 失效 / 踢下线。 不是 重新扫码即可；属正常现象。
点开一直卡在登录页、扫码后无反应 浏览器进程被强制结束（任务管理器杀进程、断电、蓝屏）→ cookie/缓存写入不完整 → 登录态损坏。 部分 用该账号的“清空档案”按钮重来（会自动备份）。
打开即报 exitCode=21 / “Settings version is not 1” 同一个账号档案被不同浏览器内核（Edge/Chrome/Chromium）打开过，档案版本不兼容。 是 见第 2、3 节：内核已强制绑定，切换会自动清空。不要手动跨内核打开同一档案。
换内核后要求重新登录 这是预期行为：切换已登录账号到另一内核时，系统强制清空旧缓存。 设计如此 无需担心，按提示确认即可。
自查清单（按顺序）：
  1. 该账号的浏览器窗口是否还开着？（同账号不能同时开两个窗口，会抢锁）
  2. 近期是否强制杀过浏览器进程？→ 用“清空档案”重置。
  3. 是否曾用别的浏览器手动打开过这个 profile 目录？→ 这就是 exitCode=21 的根因，已通过内核绑定杜绝。
  4. 以上都不是 → 纯平台踢线，重新扫码。

2账号 ↔ 浏览器内核 强制绑定（核心规则）

每个账号在第一次被某内核（Edge / Chrome / Chromium）成功打开后，该内核会被记录在 working_kernels.json（与启动器共享）。之后该账号只能用这个内核打开，杜绝跨内核损坏。

操作已登录(有缓存)未登录(空档案)
切到相同内核 允许，直接生效 允许
切到不同内核（未登录） — 允许，并记录新内核
切到不同内核（已登录） 拦截！必须“清空档案”：弹窗确认后，旧缓存备份到 profile_backups/，再绑定新内核。取消则恢复原选择。
为什么不能随便切？ 视频号档案不是“纯文本配置”，而是浏览器内核写入的二进制状态。Edge 写的档案用 Chrome 打开会因「Settings 版本号不匹配」直接崩溃（exitCode=21）。强制绑定 = 让“哪个账号=哪个浏览器”成为只读事实，从根上消除这类损坏。

“内核去重”合规看板

账号管理页顶部有合规横幅：若检测到多个账号绑定了同一个内核（非必须但不推荐），会提示你拆分；全部互异时显示绿色通过状态。注意：不同内核才是真隔离，同一个内核多账号只是“分时复用”，仍可同时登录、但共用一个浏览器进程族。

3切换内核 / 清空档案 流程

① 改内核
在账号行的内核下拉框选择新内核
→
② 判断
有缓存且目标≠原内核？→ 需清空
→
③ 确认
弹窗“将清空旧缓存，是否继续？”
→
④ 清空
旧目录备份到 profile_backups/，重建空档案，忘记旧内核，删除登录身份
→
⑤ 绑定
写入新内核，下次用新内核登录

若旧档案为空（从未登录），则第 ② 步判定“无需清空”，直接绑定，无弹窗。

也可在账号行点 “清空档案” 按钮手动重置（带确认）；用于登录态损坏、卡死、想彻底重来时。清空≠删除账号，账号配置保留，只是浏览器缓存归零。

4统一发布 vs 错峰发布

发布页顶部新增模式切换。务必先选模式，再填内容。

🔵 统一模式（默认）

  • 所有账号用同一份标题 / 描述 / 封面 / 可见性 / 原创。
  • 错峰时间归零（同时发）。
  • 每账号差异化配置被忽略（不覆盖已存配置）。
  • 适合：内容完全一致、想一键群发。

🟠 错峰模式

  • 每账号可各自不同标题/描述/封面/可见性。
  • 按 stagger_minutes 错开发布，降低限流风险。
  • 开启单原创互斥（见第 5 节）。
  • 适合：矩阵号运营、需差异化与防限流。
后端强制： 即便前端被绕过，publish_mode=unified 时服务端也会把 variants 置空、错峰归零；stagger 才保留差异化。前端隐藏+禁用只是体验层，后端才是最终闸门。

5单原创互斥（平台硬规则）

视频号平台规定：同一个视频最多只能由 1 个账号声明“原创”，其余账号若勾选会被判违规/取消。

你做的操作系统行为
在全局或某账号勾选“原创”其它所有“原创”勾选框自动取消并置灰
取消当前唯一的“原创”置灰解除，可再选另一个账号
后端发布时再次校验：仅保留 1 个原创账号，多余的全部降级为非原创
错峰模式下尤其注意：不要给多个账号都打“原创”。系统会强制只留一个，避免平台处罚。

6每号 AI 填空 / 每号合集

✨ 本号 AI 填空

在错峰模式下，每个账号卡片都有独立的“✨ 本号 AI 填空”按钮。点它会只填充该账号的标题/描述等字段（基于视频内容本地生成，不调用外部 LLM 时走兜底文案），不会改动其它账号。

📚 每号合集（Collections）

每个账号可各自选择要归入的合集（下拉框 ov_collection_<id>）。不同账号即使发同一视频，也能归到各自账号名下的不同合集。统一模式下沿用全局合集。

7ego-lite 有采用的必要吗？

结论：对本项目的自动化发布流程，没有必要采用。
维度本项目（browser-use + Playwright）ego-lite
技术形态Playwright 内核，可被代码程序化驱动Electron 桌面应用，不是 Playwright 内核
能否被自动调度能（脚本直接操控浏览器）不能（只能人手动用）
在本项目里的角色发布自动化的执行引擎仅是“手动共享浏览器”工具，无法接入发布流水线
系统组件请勿卸载： Edge 与 WebView2 是 Windows 系统组件，不要为了“腾空间”卸载它们——本项目的默认内核就依赖 Edge/WebView2 通道，卸载会导致自动化打不开浏览器。ego-lite 与本项目内核互不替代。

如果你只是想“手动用另一个浏览器看看视频号后台”，ego-lite 可作个人备用；但它不参与本项目的多账号自动发布，也不会因为装上它而增强自动化能力。
